### Summary

Finished **Epic 1: Foundation**. The database schema is live in Neon, real books from my shelves are loading through the lookup chain, and the three test queries return the right answers. Nothing is visible on the site yet, but everything the features will be built on now works.

### What I did

- Ran the schema against Neon from my terminal with `psql` (installed through Homebrew's `libpq`)
- Seeded 9 real books through the lookup: my database first, then Open Library, then Google Books
- Created a test account with books on each shelf, including a reread, and ran the three test queries:
  - **TBR:** shortlisted books first, then newest
  - **Finished reads with dates:** rereads show up as separate rows, with days taken calculated
  - **Average rating:** per year and all time
- Read through the four lookup files to understand how a book gets found and saved
- Added a fetch helper that puts the app's base path in front of every API call from the browser
- Committed and pushed

### Retro

- **Went well:** the schema held up. All three test queries were simple to write, which was the check that it needed no rework.
- **Didn't go well:** most of the time went into environment variables and config, not code.
- **Change for next time:** check that variable names match what the code expects before debugging anything else. And make failures loud instead of silent.

### Added to the backlog

- Show an error when Google Books fails or the key is missing, instead of silently skipping it
- Separate "invalid ISBN," "not found," and "lookup failed," which all show the same message right now
- Re-fetch books saved with missing fields, like a cover or page count
- *As a reader, I can add a book by hand when neither source has it* (one of my Spanish editions isn't in either)
- *As a reader, I can report or fix a book's wrong details*
